**Epic:** graph-2026-10-freeze   **Tier:** mechanical   **Execution:** sequant_run

## Context

A stranger smoke test on 2026-10-09 followed the README's headless path on a repo that had never seen Sequant: `npm install sequant@2.19.0`, `npx sequant init --yes`, `npx sequant doctor`, commit, then `npx sequant run 21`. The run passed end to end in 16 minutes. These are the first-run papercuts it hit, in the order a newcomer meets them. The `--base` PR bug from the same test is filed separately.

## Findings

1. **`doctor` (and every command) contradicts the README's install path.** The README's "Headless / CI" path says `npm install sequant` then `npx sequant init`. Every subsequent command then prints `!  Running sequant from local node_modules / For latest version: npx sequant@latest / To remove local: npm uninstall sequant` (`bin/cli.ts:172`). A newcomer is told to undo the install the README just gave them.
2. **`init`'s "Next steps" leave out the step `sequant run` needs.** They list `/spec 123`, `/exec 123`, `/qa 123` and the constitution, but not "commit `.claude/skills/`" or `sequant run`. `doctor` then warns that `.claude/skills/{spec,exec,qa}` are not committed and that phase worktrees won't see them.
3. **`doctor`'s summary undercounts warnings.** It printed two `!` lines (Skills Committed, and the Claude Code #43869 note), but the summary said `Warnings: 1` and `Passed: 19/20`.
4. **The progress timer labels the issue's elapsed time as the phase's.** At 02:48:52, one minute into exec (started 02:47:45), the log read `still running: #21 exec (12m 11s)`: the time since the issue started, not since exec started.
5. **`run --help` says `--no-rebase` skips the rebase "onto origin/main",** but the rebase uses the `--base` branch (`rebaseBeforePR(…, baseBranch)`, `batch-executor.ts:2586`).

Observed but not filed as defects: `init` adds 66 files and about 23,000 lines to commit, 20,686 of them in `.claude/skills` (an adoption-cost question, related to #1209). On a trivial three-AC issue, spec took 9m43s of the 16-minute run on Opus.

## Acceptance Criteria

- [ ] AC-1: The local-install warning no longer tells a user who followed the README to uninstall: either the README's headless path and the warning agree, or the warning is suppressed when the project's `package.json` declares `sequant` as a dependency. Evidence: a test on the warning predicate with a project whose `package.json` lists `sequant`, plus the README diff if the path changes.
- [ ] AC-2: `init`'s "Next steps" include committing `.claude/skills/` (and the other generated files) before the first `sequant run`, and name `sequant run <issue>` as a next step. Evidence: a test on the next-steps output.
- [ ] AC-3: `doctor`'s `Warnings:` count equals the number of `!` lines it printed, including the upstream-issue notes, or those notes are excluded from both. Evidence: a test on the summary with two warnings.
- [ ] AC-4: The `still running` line shows time since the current phase started. Evidence: a test on the progress formatter with a phase that started after the issue.
- [ ] AC-5: `run --help` describes `--no-rebase` as skipping the rebase onto the base branch. Evidence: the help-text diff.

## Decision for AC-1 (graph doc D-6)

Keep the README's headless install path. Suppress the local-install warning when the project's `package.json` declares `sequant` as a dependency; keep it for a stray install the project doesn't declare.
