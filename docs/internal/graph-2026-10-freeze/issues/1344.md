## Why

The README promises that "each acceptance criterion [is] checked". The only measurement behind that claim is the n=27 second-look study (#1067, `docs/investigations/qa-second-look-dataset.md`). In that study, 10 of 27 reviews caught a would-ship bug, and **7 of the 10 caught it only after the human asked "any gaps?"**. Only 3 caught it in the automated first verdict.

The automation for that follow-up shipped after the transcripts were mined on 2026-05-30:

- #582 (2026-05-06): §6d Adversarial Re-Read is required in Standard QA.
- #683 (2026-06-01): `sequant ready <issue>` runs a full-weight post-QA gate.
- #817 (2026-07-28): `sequant run --ready-gate` runs that gate inside `run`. It is **opt-in and off by default** (`bin/cli.ts:410`).

Nobody has measured what the shipped path catches. "3 of 27" describes the product before the fix, and today's number is unknown. This issue measures it, so the product claim is backed by data or reworded.

## Known obstacle: the current fixture has no headroom

In calibration (#1067 AC-6, re-graded in #1313), plain `/qa` under `sequant run --phases qa` caught **all 5 planted defects in all 5 runs** (human recall 1.00, recalibrated grader recall 1.00, in-sample). A second look cannot improve on 1.00, so this fixture alone cannot answer the question. The real catches in the n=27 study were harder: a success report with no implementation behind it (#529/#570), a test with zero assertions (#467), and a primary path broken behind passing ACs (#421, #503). #1272 needs a held-out fixture for the same reason, so build one fixture that serves both.

## Arms

- **A, first verdict:** `sequant run <N> --phases qa` (today's default).
- **B, shipped second look:** `sequant run <N> --phases qa --ready-gate`, scored on the gate's final verdict.
