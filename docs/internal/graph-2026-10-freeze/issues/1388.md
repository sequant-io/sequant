## Why

`sequant init` adds 66 files and about 23,000 lines for a newcomer to commit, 20,686 of them in `.claude/skills` (measured in the 2026-10-09 stranger smoke test, #1387). The cause is one upstream decision, not `init`:

1. The Claude Code driver starts phase agents with `settingSources: ["project"]` (`src/lib/workflow/drivers/claude-code.ts`). #19 AC-3 chose it as the way to load skills ("Loads .claude/skills/"), not as an isolation boundary.
2. So phase agents see only the project's `.claude/skills/`, never user or plugin skills. An installed plugin does not help.
3. Phase worktrees are checked out from git, so the skills must be committed (the doctor warning, #933, #1193, #1201).
4. Every adopter carries a copy that drifts. Skills changed 79 times since 2026-06-01, and each change needs `sequant sync` in every project. Cleaning up untracked files silently deletes uncommitted skills.

#1209 made a minimal install cheaper but kept the commit requirement. Customization no longer needs committed skills: `.claude/.local/skills/<name>/overrides.md` already survives updates.

## The candidate change

The Agent SDK's `query()` accepts `plugins: [{ type: "local", path }]` (docs: code.claude.com/docs/en/agent-sdk/plugins.md). The npm package already ships `plugin/` (`package.json` `files`), so every install has a plugin directory at `node_modules/sequant/plugin` with `skills/`, `hooks/` and the MCP launcher. Phase agents could load skills from there, the installed version, with nothing committed but the manifest.

Documented caveats: plugin skills are namespaced (`/sequant:spec`, not `/spec`), and the docs don't say whether `settingSources: ["project"]` filters a programmatically loaded plugin.

## Spike (no merge needed)

In a scratch repo with **no** `.claude/skills/`, run one phase through a local driver change that passes `plugins: [{ type: "local", path: <package>/plugin }]`. Launch it outside any Claude session (`launchctl submit`, per #856). Answer each question below with evidence, and record the decision it implies.

## Acceptance Criteria

- [ ] AC-1: Whether a plugin passed through `plugins` loads under `settingSources: ["project"]`, and whether a phase agent can invoke its namespaced skill (`/sequant:spec <N>`) to completion, including the `SEQUANT_PHASE` marker. Evidence: the phase transcript excerpt and the SDK version, pasted in a comment.
- [ ] AC-2: What else the loaded plugin brings into the phase agent: whether its hooks fire, and fire twice in a repo that also has `.claude/hooks/`; and whether its MCP server starts, which would bypass the #936 phase-MCP allowlist. Evidence: hook log lines and the agent's MCP server list from the same run.
- [ ] AC-3: Every place that invokes a skill by bare name and would need the `sequant:` prefix, split into `src/` (phase prompts, `phase-registry.ts`) and skill text (which is frozen while the plugin directory review is open). Evidence: a grep and the list, in a comment.
- [ ] AC-4: A recorded decision with its migration: (a) load skills from the package by default and make committed `.claude/skills/` an opt-in override; (b) keep the commit model; or (c) a hybrid. Cover how existing projects with committed skills behave. Evidence: an ADR marked Proposed, plus follow-up issues for the chosen path.
