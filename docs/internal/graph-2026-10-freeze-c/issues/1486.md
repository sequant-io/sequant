Follow-up from #1405 (PR #1468). `sequant run` now starts a first-time worktree from `origin/<branch>`, through `resolveBranchStartRef` in `src/lib/workflow/worktree-manager.ts`. `scripts/new-feature.sh` still does not. This is the seventh divergence between the script and the TS worktree path (see Prior fixes).

## Problem

On a machine with no local `feature/<N>-<slug>` branch, `templates/scripts/new-feature.sh`:
- checks only `refs/heads/<branch>` (`git show-ref --verify --quiet "refs/heads/${BRANCH_NAME}"`);
- then runs `git worktree add "$WORKTREE_DIR" -b "$BRANCH_NAME" "origin/${BASE_BRANCH}"`.

When the issue already has a pushed PR branch on `origin`, the new worktree starts from the base without the PR's commits. Pushing from it then diverges from the PR, or a force push discards the PR's work. The skills send standalone `/exec`, `/fullsolve` and `/testgen` here, and `docs/guides/git-workflows.md` documents it.

**Reproduced 2026-10-16** (`main` @ 085748480, git 2.47.1). The setup:
- a bare origin with `main` and a pushed `feature/77-add-widget` carrying one commit;
- a fresh clone;
- `gh` stubbed to return the issue title.

`bash scripts/new-feature.sh 77` printed `Creating new worktree from main...`. The worktree HEAD was `origin/main`'s commit, not `origin/feature/77-add-widget`'s. The PR's file was absent.
