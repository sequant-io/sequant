## Problem

`sequant merge --check` hard-codes `origin/main` as the base in four places in `src/lib/merge-check/`:

| Site | Use |
|------|-----|
| `combined-branch-test.ts:57` | `const BASE_REF = "origin/main"`: the combined branch is cut from it (`:264`), and the lockfile check compares against it (`:364`) |
| `index.ts:170` | `git diff --name-only origin/main...origin/<branch>`: each batch branch's `filesModified` |
| `overlap-detection.ts:38` | `git diff --unified=0 origin/main...<branch> -- <file>`: hunk ranges for overlap |
| `residual-pattern-scan.ts:61` | `git diff origin/main...<branch> --unified=0`: residual pattern scan |

On a repo whose default branch is `master` (or anything other than `main`), `origin/main` doesn't exist. The combined-branch test can't create its branch. The three diffs fail, and their callers read the empty stdout as "no changes". At `index.ts:170`, `filesModified` silently becomes `[]`, so the overlap checks, including #1454's external-PR overlap, see nothing and report clean. That's wrong output with no error.

Found by QA on #1460 (PR #1483), whose `document` finding named `combined-branch-test.ts:57`. A repo-wide `git grep` found the other three.
