**Owner ruling (2026-10-17, plan OQ-1):** a plain `sync` keeps a skills-only scope. Widening to a full install is deliberate, through `sequant init`.

Follow-up from #1409 (PR #1467). #1409's spec raised these as OQ-1 and OQ-2, and its QA marked both unresolved. #1482 is the sibling node for `update`.

## Problem

#1409 records the install scope (`groups: ["skills"]`), and `scopedRemedy` (`src/commands/sync.ts:107`) gives a partial install a fix that rewrites skills only. Plain `sync` never reads the scope for what it writes, and two of the commands that print a fix message ignore it too. They steer a skills-only install into a full install, which writes the hooks, agents and `.claude/settings.json` the install skipped. A `--force` sync also overwrites the repo's constitution (#814).

Observed on `main` @ 085748480 (dev CLI, temp repo, `init --manifest-only` + `sync --only skills`):

- **Plain `sync` at a matching version** (`sync.ts:537-583`):
  - The report-only fast path diffs the whole template set. Only `--only skills` narrows it (`filterToSkillsOnly`, `:539`), and the manifest scope is never read.
  - On an untouched skills-only install it printed `!  Version current, but 12 file(s) differ — run \`update\` or \`sync --force\`` and exited 1.
  - The 12 files are the skipped groups, the same drift #1409 removed from the pre-flight.
- **`doctor`'s Skills Version check** (`doctor.ts:649`):
  - With `.sequant-version` set to `0.0.1`, it printed `! Skills Version: Outdated (0.0.1 → 2.19.0) - run: sequant sync`.
  - The pre-flight banner of the same `doctor` run printed `Run: sequant sync --only skills`, so the two lines contradict each other.
- **Plain `sync` at a version mismatch** (`sync.ts:460`, `:754`, `:827`):
  - `skillsOnly` comes from `--only` alone (`const skillsOnly = only === "skills"`), so the manifest scope never narrows what a plain sync writes.
  - It takes the apply path, installs hooks, agents and `.claude/settings.json`, and records a full install. The #1409 test `AC-4: a full sync on a skills-only install records a full install` pins that behaviour.
  - With #1482, `update` refuses on a partial scope, so a plain `sync` is the one command left that widens a skills-only install without asking.
- **Old-style manifests** (no `groups` field, from before #1409) read as a full install by design (ADR-0015).
  - On a repo with only `.claude/skills/` and `.claude/memory/`, `doctor` printed `Version current, but 12 file(s) differ … Run: sequant sync --force (or sequant update)`.
  - It gave no hint that the repo is skills-only.
  - The owner ruled that scope is never inferred (inference can't tell "skipped" from "deleted"). The recovery is the hand edit `"groups": ["skills"]`, and nothing tells the user about it.

## Acceptance Criteria

- [ ] AC-1: On a manifest with `groups: ["skills"]` at a matching version, plain `sync` (no `--only`) counts drift only inside the install scope. With `.claude/skills/` matching the bundle it reports up to date and exits 0. With one skill file edited it reports exactly that one file, names `sync --only skills --force`, and exits 1. Evidence: `npx vitest run src/commands/sync.install-scope.integration.test.ts -t "plain sync on a skills-only install"` reports ≥ 1 passed and 0 failed (a filter that matches nothing reports all skipped and exits 0), mutation-verified by restoring the unscoped change set in the report-only fast path.
- [ ] AC-2: On a manifest with `groups: ["skills"]` and outdated skills, `doctor`'s Skills Version check names `sync --only skills` (the `scopedRemedy` text), never a bare `sync`. A full install keeps its current message. Evidence: `npx vitest run src/commands/doctor.test.ts -t "scoped install remedy"` reports ≥ 1 passed and 0 failed (a filter that matches nothing reports all skipped and exits 0), mutation-verified by restoring the bare `sync` remedy in the Skills Version check.
- [ ] AC-3: On a manifest without `groups`, when `.claude/hooks/`, `.claude/settings.json` and `.claude/agents/` are all absent, `doctor` adds one advisory line. It says the install reads as full and names the edit `"groups": ["skills"]` in `.sequant-manifest.json`. The line is never printed when any of the three exists, or when `groups` is present. `getInstallScope` is unchanged. Evidence: `npx vitest run src/commands/doctor.test.ts -t "legacy skills-only manifest"` reports ≥ 1 passed and 0 failed (a filter that matches nothing reports all skipped and exits 0), mutation-verified by deleting the advisory check.
- [ ] AC-4: No fix message printed for a partial install names `update`, `sync --force` without `--only skills`, or a bare `sync`. A test checks every per-install producer through `scopedRemedy`: `checkAndWarnSkillsOutdated` (`sync.ts:939`, `:954`), `getSkillsInstallStatus` (`version-preflight.ts:146`), the plain-sync fast path and `doctor`. Evidence: `npx vitest run src/commands/sync.install-scope.integration.test.ts -t "no remedy widens a partial install"` reports ≥ 1 passed and 0 failed (a filter that matches nothing reports all skipped and exits 0), mutation-verified by replacing `scopedRemedy`'s partial branch with the full-install text.
- [ ] AC-5: On a manifest with `groups: ["skills"]` and `.claude/skills/.sequant-version` older than the package, a plain `sync` (no `--only`) writes only under `.claude/skills/`: `.claude/hooks/`, `.claude/agents/` and `.claude/settings.json` stay absent, and the manifest keeps `groups: ["skills"]`. `sync --dry-run` previews the same scoped set. A manifest without `groups` still gets a full sync. The #1409 test `AC-4: a full sync on a skills-only install records a full install` is rewritten to this outcome. Evidence: `npx vitest run src/commands/sync.install-scope.integration.test.ts -t "plain sync keeps a skills-only scope"` reports ≥ 1 passed and 0 failed (a filter that matches nothing reports all skipped and exits 0), mutation-verified by deriving `skillsOnly` from `--only` alone again.
- [ ] AC-6: ADR-0015 says a plain `sync` keeps a partial scope and that `sequant init` is the way to widen it to a full install. Evidence: `sed -n '/^## Decision/,/^## Options/p' docs/adr/0015-install-scope-recorded-in-manifest.md | grep -c "sequant init"` prints ≥ 1 (0 today).

## Non-Goals

- Inferring the install scope from disk in `getInstallScope` or migrating a manifest automatically. The owner ruled hand edit plus `doctor` advice; inference hides real drift.
- `update`'s behaviour on a partial scope (#1482, option B).
- A manifest with `groups: []` (`init --manifest-only`, nothing installed yet). A plain `sync` there still installs every group and records a full install.
- A flag to widen from `sync` (for example `sync --full`). `sequant init` already widens (measured: a full `init --yes` on a scoped repo installs hooks, agents and `settings.json` and drops `groups`).
- `doctor`'s missing-AGENTS.md check on a skills-only install (`doctor.ts:684`, which suggests `init --force`).
- `doctor` reporting content drift at a matching version. Its Skills Version check reads only `outdated` today.
- ADR-0015's `update` sentences (#1482 owns them).
- Any edit under `plugin/`, `.claude/skills/` or `templates/skills/` (plugin freeze).
