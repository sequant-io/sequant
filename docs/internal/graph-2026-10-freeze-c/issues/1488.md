Follow-up from #1325 (PR #1466), which found during its doc fix that no CI step reads the marketplace version.

## Problem

Three files carry the release version: `package.json`, `plugin/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` → `plugins[0].version`. `docs/internal/plugin-updates.md` says "**All versions MUST match.**"

CI enforces only the first two:
- `ci.yml`'s `Check version sync` step compares `package.json` with `plugin.json`.
- `ci.yml:271` (`Validate marketplace.json structure`) and `plugin-install-test.yml:66` (line numbers at de03af8cd) check only that the marketplace file parses and has `name` and a non-empty `plugins`.

The marketplace version is written at release by `scripts/release.sh:93` (a `sed` over every `"version"` key) and by `scripts/prepare-marketplace.ts:139-149`. A hand edit, a merge resolution, or a release that skips one of those steps leaves it stale, and nothing fails.

`ci.yml` is off-limits (freeze-b D-7: the job that produces the required `test` and `canary` checks). But `scripts/plugin-mcp-pin.test.ts` already parses `marketplace.json` and `package.json` (`:22-30`, `:47-50`), and it runs in the `unit` project (`vitest.config.ts:20`), which `npm test` runs in the required `test` job. One assertion there closes the gap.
