feat(cli): `sequant mutation begin | check | render` — mutation verification refuses a dirty tree, requires a real failing run, restores by patch, and is the only producer of `SEQUANT_MUTATION` markers

- **Blocked by**: #1602

## Problem

CLAUDE.md's gate-test rule and `/qa` §6i ask the agent to mutate, run, restore and then type a `<!-- SEQUANT_MUTATION … -->` line by hand. That procedure has wiped uncommitted work five times (#817, #906, #939, #1044, #1050; #883 deleted a worktree), tripped 2 of 4 gate PRs on the marker contract (#1104), lost markers to a `}` (#1305) and to a four-hop PR-body chain (#1316). Nothing today proves the cited test ran: §6i checks only that the named file is in the diff. 33 of 184 memories are some form of "QA claimed it without running it". §4 of the founding doc.

## Decisions

| ID | Decision | Rejected alternative |
|---|---|---|
| D-2.1 | `begin --issue N` exits 2 on a dirty tree ("commit first"), records HEAD + time in `.sequant/mutations/<N>.json` | tolerating a dirty tree and stashing (the stash is the thing that gets lost) |
| D-2.2 | The agent applies the mutation with its own edit tools | a mutation DSL |
| D-2.3 | `check --issue N --ac AC-K --test <file> --name "<describe> > <case>" --mutation "<text>"`, in order, aborting at the first failure with the state file untouched: (1) no commit since `begin`; (2) `npx vitest list <file> -t <escaped name>` prints exactly one test; (3) `git add -A` then `git diff --cached --binary` captured as the patch (created and deleted files included); (4) `npx vitest run <file> -t <escaped name>` exits non-zero; (5) `git apply -R --index` the patch, then `git status --porcelain` empty; (6) the same run exits 0 without the mutation (a broken test cannot be certified); (7) append `{ac, test, name, mutation, mutatedExit, restoredExit, ranAt, sha}`. On abort the patch stays at `.sequant/mutations/<N>.patch`. All paths resolve against the current worktree, never the main checkout | reverting with `git checkout -- <file>` (misses deletions and new files; the historical wipe); accepting any non-zero exit without the restored-pass check |
| D-2.4 | The PR body stays the source of truth (#1316 owner decision, ADR-0004); QA keeps reading `$PR_BODY`. `render --issue N` prints the marker lines via `renderMutationMarker` from the state file, exec pastes them into its `## Summary`, and under the orchestrator the PR-body assembly can read the same state file directly. Skills stop typing markers (the swap is #1606). #1316 asked whether to move the channel; this leaves the channel and fixes the origin | moving the channel off the PR body (rejected on #1316); keeping hand-typed markers as a fallback (two producers) |
| D-2.5 | Scope stays gate-test ACs; widening is #939 AC-5's backtest | widening now |

## Acceptance Criteria

- [ ] AC-1: `begin` refuses a dirty tree and records HEAD on a clean one. Evidence: `npx vitest run src/commands/mutation.test.ts -t "begin"` → `≥ 2 passed, 0 failed`
- [ ] AC-2: `check` records a result only when the named test fails under the mutation and passes after the restore, and restores the tree byte-for-byte including a deleted and a newly added file. Evidence: `npx vitest run src/commands/mutation.test.ts -t "check restores"` → `≥ 4 passed, 0 failed` (test passes under mutation → exit 2, no record; test fails under mutation and passes after restore → one record with `mutatedExit != 0` and `restoredExit == 0`; test fails both ways → exit 2, no record, message names the broken test; a mutation that deletes one file and adds another → `git status --porcelain` empty after)
- [ ] AC-3: A commit between `begin` and `check` aborts the check. Evidence: `npx vitest run src/commands/mutation.test.ts -t "commit mid-mutation"` → `≥ 1 passed, 0 failed`
- [ ] AC-4: `-t` matching exactly one test is required, checked with `vitest list` before anything runs. Evidence: `npx vitest run src/commands/mutation.test.ts -t "ambiguous name"` → `≥ 2 passed, 0 failed` (two tests match → exit 2 naming both; zero match → exit 2)
- [ ] AC-5: `render` output round-trips through `parseMutationMarkers`, including a mutation text containing `}` and `>`. Evidence: `npx vitest run src/lib/workflow/mutation-marker.test.ts -t "round-trip from state"` → `≥ 2 passed, 0 failed`
- [ ] AC-6: Under the orchestrator, exec's PR body carries the markers from the state file without the agent writing them. Evidence: `npx vitest run src/lib/workflow/batch-executor.test.ts -t "mutation state"` → `≥ 1 passed, 0 failed` (a fake state file with two records → two marker lines in the body; empty state → none)
- [ ] AC-7: A reference page documents the three subcommands and the state file. Evidence: `grep -cE '^## (begin|check|render)' docs/reference/mutation-verification.md` → `3`
- [ ] AC-8: No skill-directory edits. Evidence: `git diff --name-only $(git merge-base origin/main HEAD)..HEAD | grep -cE '^(plugin/|\.claude/skills/|templates/skills/)'` → `0` (constraint)
