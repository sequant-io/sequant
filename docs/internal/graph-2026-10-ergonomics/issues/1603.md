feat(doctor,init): one hook channel per checkout — `doctor` fails when repo hooks and a sequant plugin are both active; `init`/`update` skip the hooks group when the plugin is enabled

**Epic:** graph-2026-10-ergonomics   **Tier:** mechanical   **Execution:** sequant_run   **Blocked by:** #1602

- **Blocked by**: #1602

## Problem

Sequant delivers its guard hooks two ways: `sequant init` writes `.claude/hooks/*.sh` and registers them in `.claude/settings.json`, and the plugin ships the same scripts in `hooks/hooks.json`. Nothing arbitrates. On 2026-10-26 both channels were active in both inspected checkouts (sequant itself and matcha-maps): the timing logs show the same tool call logged twice at the same second, costing 70–120 ms (pre) plus ~40 ms (post) per call. `doctor` checks 4–5 only look for `.claude/hooks` and its mode bits; `init.ts` never reads `enabledPlugins`. §3 of the founding doc.

## Decisions

| ID | Decision | Rejected alternative |
|---|---|---|
| D-1.1 | `doctor` gains a `Hook channels` check reading project `settings.json` hooks plus `enabledPlugins` in `~/.claude/settings.json` and `.claude/settings.local.json`; each enabled plugin is resolved to its install path through `~/.claude/plugins/installed_plugins.json` and counts as a channel only if its `hooks/hooks.json` registers `pre-tool.sh`; `fail` when a repo registration and such a plugin coexist; message names both sources and both fixes | matching on the plugin name (a dev plugin without a `hooks/` dir would false-positive); runtime dedupe in the hook scripts (no tool-use id in the payload; identical consecutive calls would skip a guard) |
| D-1.2 | `init` and `update` skip the hooks group when such a plugin is enabled and record `"hooks": "plugin"` in `.sequant-manifest.json`; one printed line says so | asking at `init` (OQ-1; owner may override) |

## Acceptance Criteria

- [ ] AC-1: `doctor` reports `fail` for a checkout whose `.claude/settings.json` registers `pre-tool.sh` while an enabled plugin's resolved install path carries a `hooks/hooks.json` registering `pre-tool.sh`, and `pass` otherwise. Evidence: `npx vitest run src/commands/doctor.test.ts -t "Hook channels"` → `≥ 4 passed, 0 failed` (fixtures: both active → fail naming both paths; repo only → pass; plugin only → pass; plugin enabled but its install path has no `hooks/hooks.json` → pass)
- [ ] AC-2: `init` with a sequant plugin enabled writes no `.claude/hooks/` and no hook entries in `.claude/settings.json`, and the manifest carries `"hooks": "plugin"`. Evidence: `npx vitest run src/commands/init.test.ts -t "plugin channel"` → `≥ 2 passed, 0 failed`
- [ ] AC-3: `update` on a manifest with `"hooks": "plugin"` leaves hooks absent instead of adding them. Evidence: `npx vitest run src/commands/update.test.ts -t "hooks: plugin"` → `≥ 1 passed, 0 failed`
- [ ] AC-4: The plugin-distribution doc states the one-channel rule and names the `doctor` check. Evidence: `grep -c 'Hook channels' docs/features/plugin-distribution.md` → `≥ 1`
- [ ] AC-5: No skill-directory edits. Evidence: `git diff --name-only $(git merge-base origin/main HEAD)..HEAD | grep -cE '^(plugin/|\.claude/skills/|templates/skills/)'` → `0` (constraint)

## May touch

`src/commands/doctor.ts`, `src/commands/init.ts`, `src/commands/update.ts`, the manifest reader/writer, their tests, `docs/features/plugin-distribution.md`, CHANGELOG.

## Non-Goals

- Changing the hook scripts or `hooks/hooks.json`.
- Deduplicating at runtime.

## Done when

A user with the plugin installed who runs `sequant init` gets one set of hooks, and a user who already has both learns it from `sequant doctor` with the fix spelled out.
