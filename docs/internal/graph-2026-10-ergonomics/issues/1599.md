improve(ci): the `test` job is the whole CI wall clock (6.5–9.2 min of an 8.5-min median) — shard vitest across two runners or split the integration project into its own job

## Problem

Last 40 `push` runs on `main` (2026-10-26): median 8.5 min, p75 8.8, max 9.5. The `test` job takes 6.5–9.2 min; canary 1.0, typecheck 0.5, validate-skills 0.5, validate-plugin 0.1. CI ran 300 times in 18 days, about 39 wall-clock hours, and `test` is the required check on the `main` ruleset, so every PR waits on it. The repo is public, so the cost is merge-gate latency, not minutes billed.

## Acceptance Criteria

- [ ] AC-1: The required `test` check completes in under 5 minutes at p50 over the first 20 `main` runs after merge. Evidence: `gh run list --workflow CI --branch main --limit 20 --json databaseId --jq '.[].databaseId' | xargs -I{} gh run view {} --json jobs --jq '.jobs[] | select(.name|startswith("test")) | ((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601))/60' | sort -n | sed -n 10p` → `< 5`
- [ ] AC-2: The ruleset's required check name still resolves (either `test` stays a single aggregating job, or the ruleset is updated in the same PR via `scripts/ruleset-main.sh`). Evidence: `gh api repos/sequant-io/sequant/rulesets --jq '.[] | select(.name=="CC") | .id' | xargs -I{} gh api repos/sequant-io/sequant/rulesets/{} --jq '[.rules[] | select(.type=="required_status_checks") | .parameters.required_status_checks[].context] | join(",")'` → contains every job name the workflow now runs for tests
- [ ] AC-3: No test file is skipped by the split. Evidence: the two shard logs' `Test Files` counts sum to the single-job count on `main` before the change, pasted in the PR body

## Non-Goals

- Making tests faster individually; this is parallelism only.
- Touching the plugin or skills.
