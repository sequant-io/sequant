## Problem

Phase agents get no base-branch information. The CLI resolves the base correctly: #343 added `detectDefaultBranch()` (`worktree-manager.ts:180`) and `settings.run.defaultBase`, and `phase-executor.ts` records the base per branch (`branch.<b>.sequantBaseRef`, read back by `resolveBaseRef`, :906). But the env built for the phase agent (`phase-executor.ts:1683–1710`) sets `SEQUANT_WORKTREE`, `SEQUANT_ISSUE`, `SEQUANT_ORCHESTRATOR`, `SEQUANT_PHASE` and `SEQUANT_ISSUE_TYPE`, and **no base branch**. The skills that do read one (`BASE="${SEQUANT_BASE_BRANCH:-main}"` in exec, qa, loop and testgen) therefore always fall back to `main`. `grep -rn SEQUANT_BASE_BRANCH src` finds nothing.

On a repo whose default branch is `master`, every `origin/main` in a phase's git commands fails. Measured in varius (default `master`): `git diff origin/main...HEAD --name-only` prints `fatal: ambiguous argument 'origin/main...HEAD'` and exits 128. The skill-side half of the fix is #1461.

## Acceptance Criteria

- [ ] **AC-1:** The phase env sets `SEQUANT_BASE_BRANCH` to the base branch name (no `origin/` prefix) taken from `resolveBaseRef(cwd)`, for every phase, including spec, which runs in the main checkout with no recorded base. Evidence: phase-executor unit tests for a worktree phase with a recorded `sequantBaseRef` of `origin/master` and for a no-worktree spec phase on a repo whose `origin/HEAD` is `master`, both asserting `env.SEQUANT_BASE_BRANCH === "master"`, mutation-verified by deleting the assignment
- [ ] **AC-2:** `resolveBaseRef(cwd)`'s literal `"origin/main"` fallback (used when HEAD is detached, nothing is recorded, or git fails) is replaced by `origin/<default branch of cwd>`, using `detectDefaultBranch` with an optional `cwd` argument (default `process.cwd()`, so existing callers are unchanged), so no hard-coded `main` is left on the resolver path. Evidence: a `resolveBaseRef` unit test in a temp repo whose default branch is `master`, with no recorded base, passing the temp repo as `cwd` with no `process.cwd` patch, returning `origin/master`, mutation-verified by restoring the literal
- [ ] **AC-3:** `docs/reference/run-command.md` lists `SEQUANT_BASE_BRANCH` with the other phase env variables. Evidence: `grep -n SEQUANT_BASE_BRANCH docs/reference/run-command.md` returns the new row

**Why AC-2 is in scope:** `resolveBaseRef` (`phase-executor.ts:906–937`) returns the literal `origin/main` in four places whenever there is no recorded base. Worktree phases always have a recorded base (#1234), but spec runs in the main checkout on the default branch with nothing recorded. Without AC-2, spec on a `master` repo would get `SEQUANT_BASE_BRANCH=main`, which is the bug this issue fixes. AC-2 adds no new producer. It routes the fallback to the existing `detectDefaultBranch()`. Callers that benefit too: the exec guard (`phase-executor.ts:1000`) and `hasCommitsAheadOfBase` (`worktree-manager.ts:421`, not edited).

**Graph note (graph-2026-10-freeze-b, 2026-10-16):** `detectDefaultBranch()` runs its git commands in `process.cwd()`, not in a passed `cwd` (`worktree-manager.ts:180`). Called from `resolveBaseRef(cwd)` as-is, it would read the wrong repo whenever the two differ, and AC-2's temp-repo test could only pass by patching `process.cwd`, which this repo's forks pool leaks across test files. So AC-2 adds an optional `cwd` parameter to `detectDefaultBranch`. That edits `worktree-manager.ts`, so this issue is blocked by #1406 (same file as #1405 and #1406) and runs in wave 3. When `origin/HEAD` is unset, `detectDefaultBranch` falls back to `git remote set-head origin --auto`, a network call; that path is reached only when no base is recorded (the spec phase), at most once per phase.

**Import note:** `worktree-manager.ts` already imports from `phase-executor.ts`, so importing `detectDefaultBranch` back is an ESM cycle. That's safe here, because both are function declarations called at run time, not at module load, and the repo has no cycle lint. Moving `detectDefaultBranch` out of `worktree-manager.ts` to break the cycle is allowed but not required; either way the edit lands after #1406.

## Prior fixes / producers

This is the **base-ref design cluster** from the 2026-09-30 re-patch retrospective (#1236: "base ref / two worktree producers", 5 fixes then, more since). Prior fixes: #748, #878 (diff stats against `origin/<base>`, which added `resolveDiffBase`), #890 (remaining bare `main...HEAD` consumers via `resolveDiffBase`), #1069, #1234 (worktrees record their exact base ref; the exec guard and pre-PR rebase read it), #343 (CLI default-branch detection), #1386 (`--base` PR target).

**Root cause, from the trace:** every TypeScript consumer now goes through one resolver (`resolveDiffBase` / `resolveBaseRef`), but shell and skill consumers have **no channel to it**, so each one hard-codes a guess. #890 itself changed `quality-checks.sh` from `main...HEAD` to a literal `origin/main...HEAD`, which fixed staleness but left the default branch hard-coded. This issue is that channel: it exports the resolver's answer and adds no third producer. #1136 added `SEQUANT_BASE_BRANCH` as a skill input for in-place mode, where the user sets it. Nothing in `sequant run` sets it.

Not a regression: no commit broke a working path, so nothing needs reverting.
