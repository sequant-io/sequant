## Problem

Sequant's overlap checks only see work it knows about. `src/lib/merge-check/overlap-detection.ts` compares the feature branches passed to `sequant merge`. `src/lib/assess-collision-detect.ts` compares file paths named in issue bodies. Neither looks at **open PRs on origin** that came from another session, another machine, Dependabot or a human. A peer PR that touches the same files merges in the middle of the run, and the issue's PR goes `CONFLICTING`. Sometimes the conflict is a semantic one that a textual rebase replays wrongly.

Field evidence:
- sequant #760 → #762 (PR #764) merged mid-session and touched `run-orchestrator.ts` and `types.ts`. PR #765 went `CONFLICTING` and CI silently stopped dispatching (`gh pr checks`: "no checks reported").
- ai-devtools-weekly cloudgate wave 1 (2026-10-14): two peer PRs outside the graph merged mid-wave, and one rewrote the sentence #499 was editing. The rebase became a semantic reconciliation, not a replay. The user-level `/graph-run` skill now lists "every open PR, graph member or not, whose changed files intersect the wave's file scopes" as a merge-order member. Sequant's own checks should do the same.

## Proposal

Add open PRs on origin as a source in the existing overlap machinery. Don't build a new checker. Changed files come from the platform layer (`GitHubProvider` owns `gh`). The intersection logic is reused.

- `sequant merge --check` reports open PRs that are not in the batch but whose changed files intersect the batch's changed files, as a separate finding class ("external PR overlap"). It is a warning and does not block.
- `assess-collision-detect.ts` gains a function that turns open-PR file lists into the existing `⚠ #N  Modifies <path> (overlaps #M); land sequentially` line format, with PRs written as `PR #M`.

**Freeze scoping (graph doc D-8, 2026-10-16):** `/assess` builds its collision inputs in skill prose (`assess/SKILL.md` Step 5 calls the pure functions in `assess-collision-detect.ts`). Feeding open-PR data in needs a skill edit, which the freeze blocks. So this issue ships the `assess-collision-detect.ts` function and its tests, and `/assess` starts calling it in the same post-freeze change that wires `/exec` and `/merger`. `sequant merge --check` is CLI code and is fully in scope.

## Acceptance Criteria

- [ ] AC-1: `sequant merge --check` reports each open PR on origin whose changed files intersect the batch's changed files, excluding PRs whose head branch is in the batch, as one "external PR overlap" finding naming the PR number, head branch and shared paths, at warning severity; the exit code is unchanged by these findings alone. Evidence: a merge-check unit test with a stubbed provider asserting the finding text and the unchanged exit code, mutation-verified by removing the in-batch exclusion.
- [ ] AC-2: Open-PR file lists come from one new `GitHubProvider` method, and no new `gh` spawn exists outside `src/lib/workflow/platforms/`. Evidence: a provider-stubbed test covering no open PRs, a PR with disjoint files (no finding), a PR with one shared path (one finding) and an in-batch PR (excluded), mutation-verified by making the method return every PR's files as shared, plus `git diff origin/main -- src ':!src/lib/workflow/platforms' | grep -E '^\+.*"pr", *"(list|view)"'` printing nothing.
- [ ] AC-3: `assess-collision-detect.ts` exports a function that, given an issue → paths map and open-PR file lists, returns one `⚠ #N  Modifies <path> (overlaps PR #M); land sequentially` line per overlapping PR and none for a disjoint PR. Evidence: a test in `src/lib/__tests__/assess-collision-detect.test.ts` asserting the exact line for one overlapping PR and no line for a disjoint one, mutation-verified by dropping the intersection.
- [ ] AC-4: When `gh` is unavailable or the PR list call fails, `sequant merge --check` prints exactly one line saying the open-PR overlap check was skipped and why, and otherwise behaves as today. Evidence: a test with a failing provider asserting the single skip line and an unchanged exit code.
