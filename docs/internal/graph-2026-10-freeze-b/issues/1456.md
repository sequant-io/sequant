## Problem

Phase agents run in worktrees created from `HEAD`, so they run the **committed** `.claude/hooks/`, not the copies on disk in the main checkout. #1354 added a warning for this case, but only for `.claude/skills/`: `src/lib/skills-commit-state.ts` lists tracked-but-modified files under `SKILLS_DIR_PATH` alone. A `sequant sync` or `update` that rewrites `pre-tool.sh` or `post-tool.sh` and is never committed leaves every later phase running the old hooks, with no warning anywhere.

Field evidence: ad-motion commit `e48f63e` (2026-10-07): *"pre-tool.sh and post-tool.sh were left uncommitted at 2.18.0 by the 2026-09-27 sync, so phase worktrees ran the older committed hooks."* Ten days of phases ran pre-2.18.0 guard logic with no signal.

ADR-0012 doesn't remove this. Its skills-only plugin view carries no hooks, so hooks remain committed project files.

## Proposal

Extend the commit-state check to `.claude/hooks/` and keep one shared warning. The same callers (`run-orchestrator.ts:1240`, `doctor.ts`, `sync.ts`) print it, so no caller logic changes.

## Acceptance Criteria

- [ ] **AC-1:** The commit-state check reports tracked files with uncommitted changes under `.claude/hooks/` as well as `.claude/skills/`, and the shared warning names which directory each file is in. Evidence: unit tests in a temp git repo covering a modified tracked hook (warns, names `.claude/hooks/`), a modified tracked skill (unchanged behaviour), and both clean (no warning), mutation-verified by removing the hooks path from the check
- [ ] **AC-2:** `sequant run`, `doctor` and `sync` print the hooks warning through their existing call sites, with no new call site added. Evidence: `grep -n 'getSkillsCommitState\|formatSkillsCommitWarning' src/commands/doctor.ts src/commands/sync.ts src/lib/workflow/run-orchestrator.ts` shows the same three call sites as before, and one existing caller test asserts the hooks line (`doctor`'s or `run-orchestrator`'s, not `sync`'s: `sync.ts` and its tests are #1409's scope in this graph)
- [ ] **AC-3:** Untracked hook files produce no warning (as for skills, where #1257's doctor check owns untracked files). Evidence: a unit test with an untracked file under `.claude/hooks/` showing no warning
