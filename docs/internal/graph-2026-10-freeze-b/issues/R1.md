## Problem

MCP `sequant_run` phases run the npm-pinned server (2.19.0, SDK 0.3.289), so no phase in this graph can observe its own fix (graph doc I-6). #1396's AC-1 and #1440's real-phase check need a phase run from a build of `main` after the merges. #1405's fresh-machine path needs a clone with no local branch.

## Procedure

1. After #1440, #1396 and #1405 merge: on a scratch branch off `main`, apply a local, **uncommitted** observability patch to `drivers/claude-code.ts` that writes each `system/init` message's `mcp_servers` and `claude_code_version` to a file (the #1388 spike's method; nothing in `main` logs them). Then `npm run build && npm pack` (no `prepack` script; build first). Record the `main` commit and the patch diff in the report. The patch is never pushed or merged.
2. Install the tarball into the private fixture repo used by #1388 and #1389 (named by issue number only, I-7).
3. On an account with claude.ai connectors, run one phase (`sequant run <fixture issue> --phases spec`) launched via `launchctl` (I-2).
4. On a fresh clone of the fixture repo (no local branches), with an open PR branch pushed from elsewhere, run `sequant run <that issue> --phases qa`.
