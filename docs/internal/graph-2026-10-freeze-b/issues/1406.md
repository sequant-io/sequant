## Problem

For a non-default **bare** base (`--base release` or `settings.run.defaultBase: "release"`, where the repo default is `main`):
- **Worktree creation** cuts from local `release`: `computeWorktreeBaseRef` (`worktree-manager.ts:826`) returns the bare name unchanged when it isn't the detected default.
- **Staleness** (`countCommitsBehind`, `:244`) and the recorded base compare against `origin/release`.

Local `release` can lag `origin/release` or not exist at all. In the first case a new worktree starts from an old commit while freshness reads as current. In the second, worktree creation fails or picks up an unrelated local ref.

## Acceptance Criteria

- [ ] AC-1: For a non-default bare base, worktree creation, staleness and the recorded `sequantBaseRef` all use the same ref (`origin/<base>` after a fetch, unless the base is explicitly local-only). Evidence: a temp-repo test where local `release` lags `origin/release`, asserting the new worktree's HEAD equals `origin/release`, mutation-verified by restoring the bare return in `computeWorktreeBaseRef`.
- [ ] AC-2: A base that exists only locally (no `origin/<base>`) still works, as today. Evidence: a test with a local-only base branch.
- [ ] AC-3: `--stacked` predecessor refs (local branches by design) are unaffected. Evidence: the existing #605 tests pass.
