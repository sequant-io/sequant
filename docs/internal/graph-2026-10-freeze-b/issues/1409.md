## Problem

A repo adopted with `sequant init --manifest-only` + `sequant sync --only skills` (the existing-repo path from #1209) gets a content-drift warning that never clears. Both commands the warning suggests install files the adopter deliberately left out, and the first one also overwrites the repo's own constitution.

Field case (2026-10-12): a Python repo with a repo-owned `.claude/memory/constitution.md`, adopted this way, runs through MCP `sequant_run` on npm 2.19.0. The behaviour below is the same on `main`.

1. `sync --only skills --dry-run` reports "Skills are already up to date", exit 0.
2. Every `status` / `serve` / run start still warns `Version current, but 12 file(s) differ from bundled content`.
3. `sync --force --dry-run` lists those 12 as **new** files the skills-only install never wrote: `.claude/agents/sequant-{implementer,qa-checker,testgen}.md`, `.claude/hooks/{capture-tokens,parallel-marker,post-tool,pre-tool,relay-check}.sh`, `scripts/dev/{cleanup-worktree,list-worktrees,new-feature}.sh` and `.claude/settings.json`. It also lists `Local overrides (will be overwritten): .claude/memory/constitution.md`.

## Where it comes from (main)

- `computeContentDrift` (`src/commands/sync.ts:228`) counts template changes with status `new` **or** `modified`, over the whole template set. A file that was never installed counts as drift, so a partial install drifts permanently.
- The remedy lines (`sync.ts:883-887` and `formatSkillsInstallWarning` in `src/commands/version-preflight.ts:160`) say `Run: sequant sync --force (or sequant update)`:
  - `sync --force` overwrites user-owned files, the constitution included (by design: `bin/cli.ts:240`, #814). It also installs every skipped group.
  - Bare `update` protects local overrides (`src/commands/update.ts:250`), but its apply set includes all `newFiles`. So it installs the skipped hooks, agents and `.claude/settings.json`, which changes the repo's Claude Code hooks and permissions. `update` has no `--only`.
- `.sequant-manifest.json` keeps `"files": {}` after `sync --only skills`; only `updatedAt` changes. The manifest never records which groups were installed, so the drift check has nothing to scope against.

## Why it matters

`--only skills` is the documented way to adopt sequant in an existing repo. Every such adopter gets a permanent warning, and the first fix it suggests deletes a repo-owned file. A user or agent that follows it either loses the constitution or ends up with hooks and settings they chose not to install. Here, the agent running the repo stopped only because its own rules ban overwriting the constitution.

## Owner decision (graph doc OQ-1, before exec)

Does the install record its scope in `.sequant-manifest.json`, or is scope worked out from what exists on disk? **Recommended: record it** (for example, a `groups` field that `init` and `sync --only` write). Inference from disk can't tell "deliberately skipped" from "deleted by accident". The owner's ruling is written into AC-4's text before exec (an AC prescription is changed by editing the AC, not by a comment).
