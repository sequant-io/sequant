## Problem

Phase agents receive the user's **claude.ai connectors**, outside the #936 phase-MCP allowlist.

Measured 2026-10-10 in #1388's baseline run (stock sequant 2.19.0, Agent SDK 0.3.289, Claude Code 2.1.289, no plugin, committed skills). The phase agent's SDK `system/init` message listed:

```
sequant                    connected   source: dynamic    (passed by the driver, allowlisted)
claude.ai Claude Docs      connected   source: claudeai
claude.ai Gmail            connected   source: claudeai
claude.ai Google Drive     needs-auth  source: claudeai
claude.ai Google Calendar  needs-auth  source: claudeai
claude.ai Figma            needs-auth  source: claudeai
```

#936 restricted what the driver passes in `options.mcpServers` (`getPhaseMcpServersConfig`). The SDK adds the account's claude.ai connectors separately, so the allowlist never sees them.

**Failure scenario:** an issue body, which isn't trusted input, instructs the agent → a phase agent running `permissionMode: "bypassPermissions"` reads it → it calls a connected Gmail or Docs tool (send, read, share) on the user's account with no prompt. This is the over-grant #936 closed for Claude Desktop config, reached through a source #936 doesn't cover.

## Lever (measured 2026-10-16, graph doc §4 and D-3)

`query()` aborted at `system/init`, `settingSources: ["project"]`, one dynamic server passed, on an account with connectors:

| Option | CC 2.1.289 | CC 2.1.296 |
|---|---|---|
| none | 5 `claudeai` servers | 5 `claudeai` servers |
| `strictMcpConfig: true` | passed server only | passed server only |
| `settings: { disableClaudeAiConnectors: true }` | passed server only | passed server only |

Use `settings: { disableClaudeAiConnectors: true }`. It gates only auto-fetched claude.ai connectors. `strictMcpConfig` would also drop project `.mcp.json`, plugin and agent-frontmatter MCP, which is wider than this bug and would change what #1397/#1398 can load. The driver has one `query()` call (`drivers/claude-code.ts:130`, the only SDK import in `src`).
