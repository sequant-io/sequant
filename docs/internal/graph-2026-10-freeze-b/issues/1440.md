## Problem

Phase agents do not run the user's installed `claude` CLI. They run through the Agent SDK `query()` in `src/lib/workflow/drivers/claude-code.ts:130-158`. `package-lock.json` pins `@anthropic-ai/claude-agent-sdk` **0.3.289**, which bundles Claude Code **2.1.289** (its `manifest.json` `version`). `package.json:99` declares `^0.3.289`.

So none of the Claude Code fixes from 2.1.290 through 2.1.296 reach Sequant's own phase runs, whatever version the user has installed. The README's recommended Claude Code version (≥ 2.1.288) does not govern phase agents at all. Fresh `npm install`s of Sequant already resolve a newer 0.3.29x, so CI and users may run a different bundled CLI than this repo's lockfile.

Fixes in the gap that touch phase agents (from the 2026-10-13 upstream triage):
- remote MCP reconnect backoff (v2.1.295), which matters for `mcpAllowlist` servers;
- `.mcp.json` servers switched off for a folder no longer started in headless runs (v2.1.296);
- `rate_limit_event` saying whether extra usage is on (v2.1.295), parsed in `claude-code.ts`;
- file-read-state fixes (v2.1.295);
- `disableClaudeAiConnectors` / `allowedMcpServers` applying to more MCP entries (v2.1.290). (Measured 2026-10-16: #1396's lever already works on 2.1.289, so #1396 does not wait on this issue; graph doc D-4.)

**Plan-time probe (2026-10-16):** Dependabot PR #1445 moves the lockfile to 0.3.296 (bundled CC 2.1.296). On its tree `npm ci` and `npx tsc --noEmit` both exit 0. **#1445 merges first** (the runner, with owner consent, before this issue launches; graph doc D-2). This issue then raises the `package.json` floor and adds the doc line.
