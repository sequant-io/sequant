## Problem

76 test files (30,461 lines) read a `SKILL.md` and assert on its text with `toContain`/`toMatch`. Google's testing guidance calls this shape a change detector: a transformation of the same information as the thing under test, breaking on any edit without checking behaviour. But skills are the product here, so the distinction is in how a gate is written. PR #1290 extracts the grep pattern from the skill and runs real grep on sample names — that tests the prose. A phrase-presence assertion is a checksum. This node reads every file and writes the table F-12 acts on. It changes no test.

Classes:
- **execute** — the skill section names a command or pattern the test can run (the #1290 pattern); the row names the command.
- **checksum** — the assertion checks that wording is present and nothing else; deletable under D-3's default.
- **keep** — the assertion guards a contract another tool parses (e.g. `lint:skill-gates` exact phrases, `Evidence:` grammar, `SEQUANT_MUTATION` marker); stays as is.
