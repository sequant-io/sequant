## What we want to learn

Every row names its null result first, so a green report is read for what it is.

| # | Question | Metric | Ground truth | Null result |
|---|---|---|---|---|
| G1 | Can a stranger get from the npm page to a first successful `sequant run` on a fresh machine? | commands tried before first success; wall-clock; every error line verbatim | the run log's issue status and a PR the harness fetches with `gh pr view`, never the tester's claim | success on a clean Linux box says the default path works for an agent; it says nothing about a person |
| G2 | Does the default path survive repos that are not this one? | per scenario: PR opened / CI passed / merged / `silent-wrong` / failed, with the cause line | PR state and diff from `gh`; QA's reported changed-file count compared with the PR's actual count | a scenario that passes today was never a risk; the harness earns trust only by reporting S2's silent-wrong while #1461 is open |
| G3 | When a run fails, does the output name the cause? | share of failures whose message a human classifies `names-cause` vs `symptom-only` vs `misleads`, plus a five-item blind re-read agreement | the owner's rubric read of the verbatim messages, not the tester's reaction | one episode gives a handful of failures; the share is reported, not gated |
| G4 | Which docs did the stranger need and not find? | pages opened; lookups that ended in a workaround; steps performed that no page names | the tester's command history and fetched URLs, captured by the harness | an agent reads every page; a person skips most, so "found" overstates human findability |
| G5 | Which of 33 commands and 152 flags did a first-time user touch? | commands and flags used; dormant flags attempted | the command history | feeds D-2 on #1501; it does not decide it |
| G6 | Does the run contain itself? | orphaned processes at exit; orchestrator exit code; worktree removed | process-tree snapshot and `git worktree list` after the episode | a clean container hides the host-side kill class (#856) only partly; a hang inside the container still shows |
| G7 | Does the run stay inside the boundary? | files written outside the repo; `gh` calls refused by the scoped token; network egress to hosts other than GitHub and the model API | container filesystem diff; token-scope denials counted from `gh` stderr; egress log if the runtime provides one | an API-key auth has no claude.ai connectors, so #1396's class is out of reach of this probe by construction |
| G8 | What does a stranger's first issue cost? | tokens and wall-clock per phase; USD at list price | the run log's token fields and the harness clock | one issue size; the number is for honest landing copy, not a benchmark |

## What this cannot tell us

Whether anyone would use it twice. Whether a person forms the wrong mental model. Whether the output is worth the cost. Those need the two-or-three-person pilot, which this node precedes and does not replace.

## Design

| ID | Decision | Rejected alternative |
|---|---|---|
| S-1 | A fresh container per episode (Docker locally, a GitHub Actions runner on schedule); sequant installed from npm at the tag the run names (`next` by default, `latest` on request) | the owner's machine or dev link (the 2026-10-09 smoke ran there; it cannot see install friction) |
| S-2 | The tester is knowledge-free: one instruction, one URL, a scoped token and an API key; no sequant source, CLAUDE.md, memory or skills | a session that knows the repo (that is the dogfood blind spot the whole research named) |
| S-3 | The tester runs on a non-Claude model through opencode; the phases run on Claude Code, because that is the product | Claude as tester (its priors about Claude Code fill the gaps a user has) |
| S-4 | `sequant run` is launched detached from the tester's process | a backgrounded Bash task (the 106-second kill, #856; the prior smoke used `launchctl` for the same reason) |
| S-5 | Each episode copies `sequant-example` into a private scratch repo in a scratch org and deletes it after the report is accepted | running against `sequant-example` itself (it is the public worked example; strangers' PRs would pollute it) |
| S-6 | The harness writes one report; it never files issues | auto-filing (machine-filed issues are a quarter of the repo's closures) |
| S-7 | The aggregate report lands in `docs/evidence/stranger-runs/`; transcripts are retained CI artifacts and never enter the repo | transcripts in the repo (the repo is public; agent transcripts are secret-bearing) |
| S-8 | A per-episode cost cap aborts the run and reports the partial result | unbounded (one stuck phase is 30 minutes of Opus) |

## Scenarios

- **S1 default:** a copy of `sequant-example` (TypeScript, `main`, tests, no required checks), seeded issue "Accented letters are dropped from slugs". Expected today: success.
- **S2 `master` default:** the same copy with its default branch renamed to `master`. Expected today: `silent-wrong` — the QA quality checks report 0 changed files for a diff that changed files (#1461). This scenario is the harness's own validation: it must detect a run that looks green and is not.
- **S3 legibility seed:** S1 with the phase timeout set to 60 seconds so a phase fails on time. Expected today: a failure whose message the rubric classifies; the 2026-09 memory recorded this failure reading as "Out of credits", and whether that persists is what the probe measures.
- **S4 non-npm repo** (Python, no `npm test`) and **S5 required checks** (bot PR cannot merge under a required `test` check): defined here, implemented as follow-ups (Non-Goals).

## Acceptance Criteria

- [ ] AC-1: The harness runs S1 to S3 in a fresh container and writes one report with the eight sections. Evidence: `test -f scripts/stranger/run.sh && jq -e '.install and .portability and .legibility and .docs and .surface and .containment and .boundary and .cost' docs/evidence/stranger-runs/latest.json > /dev/null && echo ok` → `ok`
- [ ] AC-2: Ground truth is fetched, not asserted: each scenario's PR fields come from `gh`. Evidence: `jq -e '[.scenarios[] | select(.pr != null) | .pr.files | length > 0] | all' docs/evidence/stranger-runs/latest.json` → `true`
- [ ] AC-3: S2 is reported as silent-wrong while #1461 is open: the QA's reported changed-file count disagrees with the PR's actual count and the verdict says so. Evidence: `jq -r '.scenarios.S2.verdict + " qa=" + (.scenarios.S2.qaReportedFilesChanged|tostring) + " pr=" + (.scenarios.S2.pr.files|length|tostring)' docs/evidence/stranger-runs/latest.json` → `silent-wrong qa=0 pr=N` with N ≥ 1 (once #1461 lands, the expected verdict becomes `success` and this AC's text is updated on the issue)
- [ ] AC-4: Every failure carries its verbatim message and an owner-filled rubric class, and the re-read agreement is recorded (owner gate). Evidence: `jq -e '[.legibility.failures[] | .message and (.class | IN("names-cause","symptom-only","misleads"))] | all and (.legibility.rereadAgreement | type == "string")' docs/evidence/stranger-runs/latest.json` → `true`
- [ ] AC-5: Docs and surface are captured as lists, not prose. Evidence: `jq -e '(.docs.pagesOpened | type == "array") and (.docs.stepsNotInDocs | type == "array") and (.surface.commands | type == "array") and (.surface.dormantFlagsTried | type == "array")' docs/evidence/stranger-runs/latest.json` → `true`
- [ ] AC-6: Containment and boundary are measured. Evidence: `jq -e '(.containment.orphans | type == "number") and (.containment.orchestratorExitCode | type == "number") and (.containment.worktreeRemoved | type == "boolean") and (.boundary.filesOutsideRepo | type == "number") and (.boundary.deniedGhCalls | type == "number")' docs/evidence/stranger-runs/latest.json` → `true`
- [ ] AC-7: Cost is reported and capped. Evidence: `jq -e '(.cost.usd | type == "number") and (.cost.wallSeconds | type == "number")' docs/evidence/stranger-runs/latest.json > /dev/null && grep -c 'STRANGER_COST_CAP_USD' scripts/stranger/run.sh` → `≥ 1`
- [ ] AC-8: The harness files nothing. Evidence: `test -d scripts/stranger && grep -rcE 'gh issue create|gh issue comment' scripts/stranger/ | awk -F: '{s+=$2} END{print "files-ok " s+0}'` → `files-ok 0`
- [ ] AC-9: It can be run on demand and on a schedule, and the release checklist names it before `latest` moves. Evidence: `grep -cE '^\s+(workflow_dispatch|schedule):' .github/workflows/stranger-run.yml` → `2` and `grep -c 'stranger' docs/internal/release-checklist.md` → `≥ 1`
- [ ] AC-10: No transcript is committed. Evidence: `git ls-files docs/evidence/stranger-runs | grep -cE 'transcript|\.jsonl$'` → `0` (constraint: holds today by construction, binding on every report PR)
- AC-1 may be classified as a gate test by `isGateTestEvidence`; the PR body then carries its `SEQUANT_MUTATION` record (remove one section from the report writer → AC-1 fails; restore).
