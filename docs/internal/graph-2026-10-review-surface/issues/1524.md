## Problem

The QA skill posts per-AC results as free-form prose (tables in some comments, bullet lists in others; the skill's own notes record ~45% format variance in past specs). The only machine marker is `SEQUANT_PHASE` with the overall verdict. A producer that parses per-AC status from that prose is either good enough to ship or it is not, and the sample taken at planning (4 issues, 24 ACs, 23 matched) is too small to say. This node measures it on every QA-marked comment since 2026-08-01 (49 exist at planning) against hand-labelled ground truth, commits the fixture that RS-02's tests run against, and writes the RD-1 line.

## Acceptance Criteria

- [ ] AC-1: A fixture of real QA comments with ground truth exists. Evidence: `ls __tests__/fixtures/qa-comments/*.md | wc -l | tr -d ' '` → `≥ 10` and `jq -e '[.[] | .acs | length] | add >= 40' __tests__/fixtures/qa-comments/expected.json > /dev/null && echo ok` → `ok` (each fixture is a verbatim public comment from this repo; `expected.json` maps fixture → `[{id, status}]` with status in `met|not_met|pending|unknown`, labelled by hand before the parser is written)
- [ ] AC-2: The coverage script runs over every QA-marked comment since 2026-08-01 (49 at planning) and reports a number. Evidence: `npx tsx scripts/qa/ac-status-parse-coverage.ts --since 2026-08-01 --json | jq -e '.comments >= 45 and (.acs | type == "number") and (.classified | type == "number")' > /dev/null && echo ok` → `ok`
- [ ] AC-3: Against the fixture, the candidate parse's precision is reported, not only recall. Evidence: `npx tsx scripts/qa/ac-status-parse-coverage.ts --fixture --json | jq -e '(.precision | type == "number") and (.recall | type == "number")' > /dev/null && echo ok` → `ok` (a stray `MET` in prose near an AC id must count as a false positive)
- AC-1 and AC-3 are classified as gate tests by `isGateTestEvidence`; the PR body carries a `SEQUANT_MUTATION` record for each (delete one fixture's entry from `expected.json` → the `≥ 40` check fails; remove the false-positive case from the fixture → precision reads 100% and the record names it; restore).
- [ ] AC-4: The evidence file records the numbers and the RD-1 line. Evidence: `grep -cE '^RD-1: (parser-now|marker-first) — coverage [0-9]+% on [0-9]+ comments, precision [0-9]+%' docs/evidence/review-surface/ac-parse-coverage.md` → `1`
- [ ] AC-5: Eight fixtures are re-labelled blind at the end and the agreement is recorded (human-read metric rule). Evidence: `grep -cE '^Re-read: [0-9]+ of 8 agreed' docs/evidence/review-surface/ac-parse-coverage.md` → `1`
