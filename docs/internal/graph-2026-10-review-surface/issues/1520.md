## Problem

Agent PRs are merged fast here (median 3.7 h open-to-merge over the last 100 merged PRs) against a median fix of 132 test lines and 45 source lines, at roughly 55 issues a week. Reading every line is not possible at that volume, and the data says where the misses are: re-patches of the same artifact (~78% in the 2026-09-30 retrospective), the four workflow files that took 40 of 83 fixes, tests that mock the one subprocess seam or assert markdown wording, and errors dropped by policy. The per-AC verdict answers "did it do what I asked" and nothing else. The GTM brief's cold reader also named the constraint: the audience distrusts summaries written by the author of the code.

So the reviewer needs a **computed** partition of the diff, posted where the merge decision is made, with the residue first:

1. **Residue** — hunks in files no AC's evidence cites; hot files (≥ 3 fix commits in 28 days, from `git log`); deleted or weakened tests (`--numstat` on test paths); tautology-detector hits (`--json`); size over the budget; later, the run's suppressed-error count (#1504). Each line carries the command that produced it. The human reads this in full.
2. **Tests** — each test file in the diff with its seam class (real dependency / `child_process` or module mock / prose gate reading `SKILL.md`) and whether a `SEQUANT_MUTATION` record exists for it (`parseMutationMarkers`). A mock of a type the project does not own is flagged.
3. **Explained** — files that an AC's declared `Evidence:` (#938) or verdict line names, with the AC id. Sampled, not read.

Attribution is a parse, not a model: an AC "explains" a file only when its evidence clause names that path, test file or command whose arguments name it. Measured today over the 80 most recently closed issues: 258 ACs, 257 with an `Evidence:` clause, **149 (58%) name a file or command**. The rest explain nothing, so their hunks fall into residue by default. Residue is the conservative default; explained is earned.
