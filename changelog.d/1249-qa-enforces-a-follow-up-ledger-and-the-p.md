**`/qa` enforces a follow-up ledger, and the PR body lists QA's follow-ups (#1249).** Every item an earlier phase deferred (spec's Open Questions and out-of-scope notes, exec's PR-body follow-ups, QA's own `document` findings) must end `filed #N`, `fixed in this PR` or `dropped: <reason>`. An unresolved item caps the verdict at `AC_MET_BUT_NOT_A_PLUS` through a new §7 gate, `followup_ledger_status`, in both Standard and Simple Fix mode. QA writes each `document` finding's resolution as a suffix on its description, and `sequant run`'s PR body renders the latest QA pass's `document` findings as a `## Follow-ups` checklist; a finding with no resolution reads `unresolved`. The sibling-site scan now names the defect class it searched (e.g. "every git call without `-C <target>`") rather than searching for the changed code, and an AC that promises end-to-end delivery (e.g. "surfaces in the PR body") can no longer be marked MET with that path under "Not tested": QA runs it or marks the AC PENDING. `qa/SKILL.md` did not grow. See ADR-0007.
