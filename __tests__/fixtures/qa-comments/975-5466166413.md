### Code Review

**Strengths:**
- Single choke point: role resolution lives only in `resolvePhasePolicies`, consumed identically by both ExecutionConfig producers — the #833 drift guard is enforced by a source-inspection test, not just convention.
- Fail-loud contract honored: missing role throws at config-resolution time (before any session), message names the role and the available map — exactly AC-2.
- Clean backward-compat: raw strings and `modelRoles === undefined` both bypass resolution; `enrichPhasePoliciesFromResults` returns the same reference when nothing to enrich (no needless allocation).
- Family-alias defaults (`fast=sonnet`, `strong=opus`, `frontier=fable`), no dated IDs — matches the phase-0 finding that aliases track releases.

**Issues:**
- **AC-4 phase-marker emission is schema-deep only.** `PhaseMarkerSchema` gains `requestedModel`/`resolvedModel`, but nothing constructs a marker carrying them (`formatPhaseMarker` has no callers; the exec/qa skill marker text was not updated). At runtime, emitted phase markers will not contain these fields. The durable benchmark surface the design motivates (#916/#944) is the run-metrics/run-log path, which **is** fully wired — so practical impact is low, but the literal "the phase marker record" clause is not satisfied at runtime.

**Suggestions:**
- Wire phase-marker emission (skill marker text + a caller that populates the fields from `PhaseResult.resolvedModel` / configured `requestedModel`), or, if intentionally deferred to a follow-up, note the deferral on the AC.
